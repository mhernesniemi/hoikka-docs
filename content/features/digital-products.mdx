# Digital Products

Hoikka supports both physical and digital products. Each product has a type from `productTypes` in `hoikka.config.ts`, and the type's `fulfillment` (`physical` or `digital`) determines checkout behavior.

- **Physical products** require a shipping address and go through the shipping provider flow.
- **Digital products** skip shipping entirely. After payment, delivery emails are sent with the product content.

## Enabling Digital Products

Out of the box the store sells only physical products. Add a type with digital fulfillment:

```typescript filename="hoikka.config.ts"
productTypes: {
	physical: { label: "Physical", fields: [] },
	digital: { label: "Digital", fields: [] }
}
```

- A type keyed `digital` is delivered as a download; any other key ships unless it sets `fulfillment: "digital"`. Keys are yours to name, e.g. `stockItem: { label: "Stock item", fields: [] }` or `ebook: { label: "E-book", fields: [], fulfillment: "digital" }`.
- With a single type, the type selector is hidden and all products use that type.
- `defaultProductType` is the type for newly created products (default: the first one).

## Setting a Single Product as Digital

With two or more types, a **Product Type** card appears in the admin product page sidebar. Use it to switch a product between types; a type with digital fulfillment shows the **Digital File** card.

You can also update the type programmatically:

```typescript
await productService.update(123, { type: "digital" });
```

An order line pins how it was sold at payment, so changing a type's fulfillment later never changes an order that is already paid.

## Checkout Behavior

When all items in a cart are digital:

1. The shipping step is skipped and no shipping address is collected (a contact email is still required)
2. Stock validation is skipped
3. After successful payment, the order transitions to `paid` and delivery emails are sent

When a cart contains a mix of physical and digital products, the standard shipping flow applies; the digital items are still delivered by email.

## Delivery Emails

`digitalDeliveryService.deliverOrder(orderId)` (`src/lib/server/services/digitalDelivery.ts`) sends one email per digital product via Resend. It requires `RESEND_API_KEY` (and optionally `RESEND_FROM_EMAIL`); without them, delivery is skipped. A delivery failure never fails the order.
