# Installation

Hoikka is a SvelteKit store that runs on SQLite and deploys to either a Node.js server or Cloudflare Workers. The same codebase targets both — you pick with a single `HOIKKA_TARGET` env var.

## Scaffold a new store

The recommended way to start is the `create-hoikka-app` installer. It clones the template, writes a `.env`, optionally seeds demo data, and — for the Cloudflare target — can provision D1 + R2, apply migrations, set secrets, and deploy.

```bash
pnpx create-hoikka-app my-store
```

It prompts for:

- **Deploy target** — *Local / Node.js* (SQLite file + local uploads) or *Cloudflare* (Workers + D1 + R2).
- **Demo content** — seed demo products (local target only).

Flags make it scriptable: `--target=local|cloudflare`, `--seed` / `--no-seed`, `--yes`.

```bash
cd my-store
pnpm dev
```

Your store runs at `http://localhost:5173`:

- Storefront: `http://localhost:5173`
- Admin: `http://localhost:5173/admin`

On first visit to `/admin` you are sent to `/admin/setup` to create the first admin account.

## Manual setup

If you'd rather clone the repo directly:

```bash
git clone https://github.com/mhernesniemi/hoikka
cd hoikka

# Install dependencies (Node >= 20)
pnpm install

# (Optional) seed demo products
pnpm seed

# Start the dev server
pnpm dev
```

`pnpm seed` creates and migrates the SQLite database on first run. Without it, migrations apply automatically the first time the server touches the database. The default database file is `./data/hoikka.db` — override it with `DATABASE_URL`.

<Callout type="info">
Copy `.env.example` to `.env` and set at least `BETTER_AUTH_SECRET`. See [Configuration](/getting-started/configuration) for the full list.
</Callout>

## Node.js and containers

`pnpm build` produces a plain Node server in `build/`; start it with `pnpm start` (`node build`). The same build runs in a container, for example with Kamal on a VPS:

- **Database** — keep `DATABASE_URL` on a mounted volume (e.g. `/data/hoikka.db`). Migrations from `MIGRATIONS_DIR` (default `./drizzle`, so copy that folder into the image) apply on startup.
- **Uploads** — either on the same volume (`UPLOADS_DIR`) or in an S3-compatible bucket (`S3_BUCKET` and friends, see [Configuration](/getting-started/configuration#s3-compatible-storage-node-target)). Move the resized-image cache with `CACHE_DIR` to keep it out of backups.
- **Health check** — `GET /api/health` returns `200 {"ok":true}` when the database answers with the schema in place, `503` otherwise. It is public, uncached, and skips auth, so point the proxy or deploy tool's healthcheck at it.
- **Origin** — behind a TLS-terminating proxy (kamal-proxy, Caddy, nginx) set `ORIGIN=https://your-store.example`, or adapter-node sees `http://` and rejects form posts as cross-site.
- **Body size** — set `BODY_SIZE_LIMIT=209715200` so 200 MB digital deliverables can be uploaded (see `.env.example`).
- **Background work** — the outbox and scheduled tasks run on an in-process interval, started by the first request (the health check counts). Overlapping containers during a rolling deploy are safe: each outbox event and each task run is claimed in the database before it runs, so nothing runs twice.

```bash
docker run -p 3000:3000 \
  -v hoikka-data:/data \
  -e DATABASE_URL=/data/hoikka.db -e UPLOADS_DIR=/data/uploads -e CACHE_DIR=/data/cache \
  -e ORIGIN=https://store.example.com -e BETTER_AUTH_SECRET=... -e BODY_SIZE_LIMIT=209715200 \
  my-store
```

## Cloudflare

For the Cloudflare target the app runs on Workers with **D1** (database) and **R2** (asset storage). `create-hoikka-app` can set this up for you; to do it by hand:

```bash
# Switch the target
HOIKKA_TARGET=cloudflare

# Create the resources named in wrangler.jsonc
pnpm exec wrangler d1 create hoikka-db      # copy the id into wrangler.jsonc
pnpm exec wrangler r2 bucket create hoikka-assets

# Apply migrations to the remote D1 database
pnpm db:migrate:cf

# Set secrets
pnpm exec wrangler secret put BETTER_AUTH_SECRET

# Build for Cloudflare and deploy
pnpm deploy:cf
```

Run the Cloudflare target locally (bindings via miniflare) with `pnpm dev:cf`.
