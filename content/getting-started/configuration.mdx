# Configuration

Hoikka is configured through environment variables. Copy `.env.example` to `.env` to get started.

Every variable the app reads is declared in `src/env.ts` and read from `$app/env/private` (or `$app/env/public` for the `PUBLIC_` ones). All of them are optional. A variable that isn't declared there can't be read, so add your own to the list:

```typescript filename="src/env.ts"
export const variables = defineEnvVars({
	// ...
	WEBHOOK_SECRET_ERP: optional
});
```

The `SSO_<ID>_*` variables are declared automatically for each provider in `hoikka.config.ts`.

## Deployment target

A single variable decides how the app is built and where the database and storage come from. `vite.config.ts` reads it (environment first, then `.env`) to pick the adapter and to swap the other target's modules for stubs.

```bash filename=".env"
# "node" (default) or "cloudflare"
HOIKKA_TARGET=node
```

| Target | Adapter | Database | Storage |
| --- | --- | --- | --- |
| `node` | `@sveltejs/adapter-node` | `better-sqlite3` file | local filesystem, or an S3-compatible bucket |
| `cloudflare` | `@sveltejs/adapter-cloudflare` | D1 binding | R2 binding |

Switching targets is just flipping this value (and rebuilding). Run the Cloudflare target locally with `pnpm dev:cf`.

## Required variables

### Better Auth

```bash filename=".env"
BETTER_AUTH_SECRET=
```

`BETTER_AUTH_SECRET` signs sessions and is required. See [Authentication](/core/authentication).

## Optional variables

### Auth base URL

```bash filename=".env"
BETTER_AUTH_URL="https://your-store.example"
```

Not needed normally — auth derives the base URL from the incoming request. Set it only to override, e.g. behind a reverse proxy that doesn't forward the public origin.

### Database location (node target)

```bash filename=".env"
# Defaults to ./data/hoikka.db — set only to override.
DATABASE_URL="./data/hoikka.db"
```

Only used on the node target. The Cloudflare target ignores it and uses the D1 binding (`DB`).

```bash filename=".env"
# Refuse to start when the DATABASE_URL file is missing
DATABASE_MUST_EXIST=1
```

Without it, a missing file is created and migrated, which is what you want on a first run and in development. In production that also means a mistyped path starts an empty store that `/api/health` reports as healthy. With the flag set, startup fails with an error naming the path instead. See the [first deploy](/getting-started/installation#nodejs-and-containers) flow.

### Paths (node target)

```bash filename=".env"
UPLOADS_DIR="./data/uploads"          # uploaded files (fs storage)
CACHE_DIR="./data/uploads/.cache"     # resized images; defaults to <UPLOADS_DIR>/.cache
MIGRATIONS_DIR="./drizzle"            # migrations applied on startup
```

All optional. The resized-image cache is regenerable, so pointing `CACHE_DIR` outside the uploads keeps it out of backups. `MIGRATIONS_DIR` lets a built image ship the `drizzle/` folder anywhere.

### S3-compatible storage (node target)

```bash filename=".env"
S3_BUCKET=
S3_ACCESS_KEY_ID=
S3_SECRET_ACCESS_KEY=
S3_ENDPOINT="https://s3.example.com"  # unset for AWS S3; set = path-style URLs
S3_REGION=us-east-1                   # default
S3_PREFIX=                            # optional key prefix, e.g. "my-store"
```

Setting `S3_BUCKET` moves uploads from `UPLOADS_DIR` to any S3-compatible bucket (AWS S3, UpCloud Object Storage, Hetzner, MinIO). See [Assets](/features/assets#s3-compatible-storage).

### OAuth (Google)

```bash filename=".env"
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
```

Google sign-in is enabled only when both are set.

### Email (Resend)

```bash filename=".env"
RESEND_API_KEY=
RESEND_FROM_EMAIL="noreply@yourdomain.com"
```

Used for digital product delivery emails. Optional — if not set, email delivery is skipped.

### Payments (Stripe)

```bash filename=".env"
STRIPE_SECRET_KEY="sk_..."
PUBLIC_STRIPE_PUBLISHABLE_KEY="pk_..."
```

Optional for getting started — a mock payment provider is used for development and testing. Get credentials from your [Stripe Dashboard](https://dashboard.stripe.com).

### Other

```bash filename=".env"
# Read-only guard: blocks admin POST/mutations for public demos.
DEMO_MODE=

# Absolute site URL for the sitemap (falls back to the request origin).
PUBLIC_SITE_URL=
```

`SENTRY_DSN` sends server errors (5xx) and failing scheduled tasks to Sentry, without the SDK.

Integration variables (`TASKS_SECRET`, `ORDER_WEBHOOK_URL`, `ORDER_WEBHOOK_SECRET`, and `WEBHOOK_SECRET_<PROVIDER>`, which you declare in `src/env.ts`) are covered in [Integrations](/integrations/overview).

<Callout type="info">
On Cloudflare, secrets are set with `wrangler secret put <NAME>` rather than an `.env` file.
</Callout>
